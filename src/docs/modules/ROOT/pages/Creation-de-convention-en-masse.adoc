= Création de conventions en masse
:reftext: Création de conventions en masse
:navtitle: Création de conventions en masse
:sectnums:

Ce guide décrit le parcours de *création de conventions en masse* dans ESUP-Stage : paramétrage préalable, utilisation du wizard par groupe d'étudiants, finalisation et dépannage.

Il s'adresse aux gestionnaires, responsables gestionnaires et administrateurs métier.

[NOTE]
====
Ce document décrit le comportement de la ligne *3.2.x*.
Le parcours *individuel* d'une convention (création par l'étudiant ou le gestionnaire, circuit de validation) n'est pas traité ici.
====

== Public et principes

La création en masse permet à un gestionnaire de constituer un *groupe d'étudiants* et de produire leurs conventions en une seule opération, lorsque la mise en stage est organisée côté scolarité / gestion.

[cols="2,3", options="header"]
|===
|Parcours |Caractéristique

|Individuel (étudiant ou gestionnaire)
|Circuit de validation configurable au centre (pédagogique, vérification administrative, administrative).

|En masse (gestionnaire)
|Après *validation des conventions* du groupe, chaque convention générée est marquée comme créée en masse et *déjà validée* (création, pédagogique, vérification administrative et validation administrative). Le circuit habituel est donc contourné.
|===

Menu applicatif : *Création des conventions en masse* → *Créer des conventions en masse* / *Gestion des groupes* / *Template de mails*.

== Prérequis de paramétrage

Sans ces éléments, l'ajout d'étudiants au groupe ou la génération des PDF échoue le plus souvent.

=== Droits

Fonction applicative : `CREATION_EN_MASSE_CONVENTION` (écran *Paramétrage de l'application* > *Rôles*).

[cols="2,3", options="header"]
|===
|Action |Droit minimal

|Voir le menu et consulter les groupes
|Lecture

|Créer / modifier un groupe, renseigner les onglets
|Création / modification selon l'action

|*Valider la creation/modification des conventions* (finalisation)
|*Validation*
|===

Par défaut à l'installation, les rôles *ADM*, *RESP_GES* et *GES* disposent de tous les droits sur cette fonction ; *ENS* et *ETU* n'en ont aucun. La matrice peut être modifiée par l'administrateur.

=== Centres de gestion et SI scolarité

* centres de gestion validés avec critères SI (composante / étape) cohérents ;
* ESUP-SISCOL opérationnel (voir xref:ESUP-SISCOL.adoc[]) ;
* templates de convention PDF et templates de mails de groupe.

[WARNING]
====
ESUP-SISCOL peut autoriser l'activation simultanée de `mode_apogee` et `mode_pegase`. En pratique, une instance (ou une base de test) qui mélange les deux SI scolarité peut produire des comportements instables (étudiants listés puis erreurs en aval). Pour la création en masse, privilégier une configuration et un jeu de données *homogènes* (un SI scolarité de référence par environnement).
====

=== Comprendre les informations renvoyées par le SI scolarité

Lors de l'ajout d'un étudiant au groupe, ESUP-Stage interroge le *SI scolarité* (Apogée ou Pégase) via *ESUP-SISCOL*. Ce n'est pas le gestionnaire qui saisit les codes de régime dans le wizard : ils sont *remontés automatiquement* pour chaque étudiant / année.

Les termes suivants sont utiles pour paramétrer correctement les types de convention :

[cols="2,3", options="header"]
|===
|Terme |Signification

|*SI scolarité*
|Système qui porte les inscriptions et les régimes des étudiants (Apogée ou Pégase dans votre établissement).

|*ESUP-SISCOL*
|Composant qui fait le lien entre ESUP-Stage et le SI scolarité (et l'annuaire). Voir xref:ESUP-SISCOL.adoc[].

|*Régime d'inscription*
|Mode d'inscription de l'étudiant pour une année universitaire (par exemple formation initiale ou continue). C'est cette information qui permet de choisir automatiquement le *type de convention*.

|*Libellé court du régime* (`licRegIns`)
|Abréviation du régime telle que renvoyée par le SI (exemples fréquents : `FI`, `FC`, `INITIALE`…). Ce n'est *pas* le diplôme « licence » : « lic » désigne ici un *libellé court*. C'est la *première* valeur utilisée pour retrouver le type de convention.

|*Code du régime* (`codRegIns`)
|Code du régime renvoyé par le SI. Utilisé en *repli* si aucun type ne correspond au libellé court.

|*Code* du type de convention (`codeCtrl`)
|Champ *Code* dans `Tables des nomenclatures` > *Type de convention*. Il doit être *identique* (sans tenir compte de la casse) au libellé court ou, à défaut, au code du régime remonté par le SI.

|*Template PDF*
|Modèle d'impression de la convention, associé à un type et à une langue (au minimum `fr`).

|*Césure*
|Situation particulière (cursus aménagé) qui peut imposer un type de convention dédié, prioritaire sur le régime habituel.
|===

==== Comment connaître les valeurs pour votre établissement ?

Ces codes ne sont pas affichés dans le wizard de création en masse. Pour les identifier :

* en cas d'erreur `Type de convention non trouvé`, les *logs applicatifs* consignent le code du régime et le libellé court (`codRegIns`, `licRegIns`) pour l'étudiant concerné ;
* sinon, consultez le référentiel des régimes dans votre SI scolarité, ou demandez à la DSI / scolarité centrale les valeurs réellement remontées via ESUP-SISCOL.

Les nomenclatures livrées avec ESUP-Stage peuvent déjà contenir des *Codes* de type adaptés à Apogée (`FI`, `FC`, …) ou à Pégase (`INITIALE`, `CONTINUE`, …) : adaptez-les à *votre* référentiel.

=== Types de convention et modèles PDF

À l'ajout d'un étudiant dans le groupe, l'application détermine automatiquement un type de convention à partir du régime d'inscription renvoyé par le SI :

. recherche d'un type *actif* dont le *Code* est égal au *libellé court du régime* ;
. si aucun résultat, même recherche avec le *code du régime* ;
. le cas échéant, remplacement par le type césure lorsque le cursus aménagé l'impose ;
. si aucun type n'est trouvé → erreur `Type de convention non trouvé`.

.Actions de paramétrage
. Ouvrir `Tables des nomenclatures` > *Type de convention*.
. Pour chaque régime utile dans votre établissement, disposer d'un type *actif* dont le *Code* correspond au libellé court du régime ou, à défaut, au code du régime (voir section précédente).
. Associer à chaque type utilisé un *template PDF* pour chaque langue concernée (au minimum `fr`).

==== Deux mécanismes distincts à ne pas confondre

[cols="2,3", options="header"]
|===
|Mécanisme |Règle

|Affectation automatique du type *à l'ajout d'un étudiant* au groupe
|Le *Code* du type doit correspondre au libellé court du régime, puis au code du régime (voir ci-dessus). Sans correspondance, l'ajout échoue.

|Liste *Type de convention du groupe* (onglet *Cadre du stage*)
|Propose les types *actifs* qui disposent d'un template PDF. Cette liste *n'est pas filtrée* par le régime de chaque étudiant.
|===

[IMPORTANT]
====
Un type peut apparaître dans la liste du *Cadre du stage* (actif + template) et pourtant provoquer `Type de convention non trouvé` à l'ajout d'étudiants si son *Code* ne correspond pas au régime remonté par le SI. Les deux réglages sont complémentaires.
====

=== Autres prérequis

* *Structures d'accueil* présentes en base (affectation manuelle ou import CSV par *RNE* / *SIRET* — identifiants nationaux de l'établissement d'accueil — dans le wizard).
* *Templates de mails* dédiés aux groupes (menu *Template de mails*), pour l'envoi depuis la gestion des groupes.

== Finalisation : créer le groupe ou valider les conventions

L'onglet *Finaliser/Valider la creation* (ou *modification* si le groupe existe déjà) propose deux actions distinctes.

[cols="2,2,3", options="header"]
|===
|Bouton |Effet |Résultat métier

|*Créer le groupe*
|Enregistre le groupe hors brouillon (il apparaît dans *Gestion des groupes*).
|Les conventions *finales* ne sont *pas* encore générées / validées.

|*Valider la creation/modification des conventions*
|Fusionne les données groupe / étudiant et génère les conventions finales.
|Chaque convention obtenue a `creationEnMasse = true` et les validations suivantes à *vrai* : validation de création, validation pédagogique, vérification administrative, validation administrative.
|===

Le bouton *Valider la creation/modification des conventions* est grisé tant que le parcours n'est pas complet. Il nécessite le droit *Validation* sur `CREATION_EN_MASSE_CONVENTION`.

[NOTE]
====
*Créer le groupe* ne remplace pas la validation des conventions. Utilisez-le pour figer un brouillon de groupe ; utilisez *Valider… les conventions* pour produire les conventions exploitables.
====

== Parcours wizard (résumé)

Menu : *Création des conventions en masse* > *Créer des conventions en masse*.

[cols="1,2,2", options="header"]
|===
|Onglet |Rôle |Points d'attention

|*Sélection d'un groupe d'étudiants*
|Code / nom du groupe ; recherche et ajout d'étudiants via le SI scolarité.
|C'est ici que la résolution automatique du type peut échouer (`Type de convention non trouvé`). Un seul brouillon de groupe en cours de création est autorisé par utilisateur.

|*Informations relatives au stage*
|Informations de stage au niveau groupe ou par étudiant.
|Doit être validé pour progresser.

|*Cadre du stage*
|Type de convention du *groupe* ; édition du cadre par étudiant (formation, langue, etc.).
|La barre de progression de cet onglet ne conditionne *pas* l'activation du bouton final de validation des conventions. Le type choisi pour le groupe sert notamment à l'impression.

|*Etab. d'accueil*
|Structure d'accueil (manuelle ou import CSV).
|Les onglets *Service d'accueil*, *Tuteur professionnel* et *Signataire* restent inaccessibles tant qu'aucune structure n'est complète (groupe ou tous les étudiants).

|*Service d'accueil*
|Service rattaché à la structure.
|Exige une structure complète ; sélection homogène (même structure) pour certaines actions groupées.

|*Tuteur professionnel*
|Contact tuteur.
|Exige une structure et un service complets ; message possible : « Il faut sélectionner des étudiants ayant le même service ».

|*Enseignant*
|Enseignant référent.
|

|*Signataire*
|Signataire de la convention (libellé paramétrable ; valeur par défaut : *Signataire*).
|Exige une structure complète.

|*Finaliser/Valider la creation* (ou *modification*)
|Créer le groupe et/ou valider les conventions.
|Voir section précédente.
|===

== Après la création

Depuis *Gestion des groupes* :

* modifier un groupe déjà créé ;
* dupliquer un groupe ;
* envoyer des mails (templates de groupe) avec les PDF ;
* télécharger une archive ZIP des conventions.

== Dépannage

Les messages ci-dessous sont ceux renvoyés par l'application en création en masse (libellés exacts).

[cols="2,2,3", options="header"]
|===
|Symptôme / message |Cause probable |Action

|`Type de convention non trouvé`
|Aucun type dont le *Code* égale le libellé court du régime puis le code du régime ; type inactif ; cas césure non couvert.
|Créer ou corriger le type et son *Code* ; consulter les logs (valeurs de régime) ou le référentiel SI ; associer un template PDF au type.

|`Aucun inscription trouvée`
|L'inscription choisie ne correspond plus aux données SI.
|Retirer / ré-ajouter l'étudiant ; vérifier année, composante, étape.

|`Code groupe déjà existant`
|Code de groupe en doublon.
|Choisir un autre code.

|`Vous avez déjà un groupe en cours de création`
|Brouillon non terminé pour l'utilisateur.
|Finaliser, abandonner ou reprendre le brouillon existant.

|`Aucun étudiant à ajouter`
|Liste d'ajout vide.
|Sélectionner au moins un étudiant.

|Bouton *Valider… les conventions* grisé
|Onglets incomplets (infos stage, structures, services, tuteurs, enseignants, signataires…).
|Compléter les onglets concernés. L'onglet *Cadre du stage* ne bloque pas ce bouton à lui seul.

|« Aucune langue disponible pour ce type de convention. »
|Aucun template pour la langue demandée sur ce type.
|Ajouter le template PDF pour la langue (ex. `fr`).

|« Vous n'êtes inscrit à aucune formation éligible. »
|Aucune inscription / formation éligible pour l'étudiant dans le cadre édité.
|Vérifier les inscriptions SI et le rattachement au centre.

|« Il faut sélectionner des étudiants ayant la même structure » / « … le même service »
|Action groupée sur un ensemble hétérogène.
|Filtrer la sélection avant l'action.

|`Aucune structure trouvée pour le RNE/SIRET…` (import CSV)
|Structure absente en base.
|Créer la structure puis réimporter.

|`Template convention {libelle}-{codeLangue} non trouvé`
|Impression sans modèle pour le couple type / langue.
|Créer le template manquant.

|Étudiants listés puis erreurs en aval
|Environnement de test hétérogène (deux SI scolarité / données mixtes).
|Homogénéiser la config SISCOL et le jeu de données de test.
|===
